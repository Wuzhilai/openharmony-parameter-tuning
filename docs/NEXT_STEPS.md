# 后续研究与成员交接

以下为建议任务，不是已经完成的分工。由负责人据成员意愿登记执行人与复核人。

| 优先级 | 工作 | 完成标准 |
|---|---|---|
| P0 | 固定内存请求轨迹 | alloc/free/size 在运行前生成；所有参数同一 seed 的请求轨迹哈希相同；失败不改变后续请求；明确无对象 free 的处理 |
| P0 | 分离失败诊断与计时 | 内层保留失败计数，诊断统一在计时结束后输出；原版本对照保留；新协议单独归档 |
| P0 | 重做内存评估 | 修改协议版本，训练/验证/测试全部重跑；比较失败率、成功操作延迟、占用，不只比较加权分数 |
| P1 | 全空间参考与简单基线 | 18/20 个配置全覆盖；随机、BO、查表及简单阈值规则在新保留集比较；报告总调用和计算成本 |
| P1 | 验证采样成本摊销 | 将 pilot、推理、应用、运行、清理费用纳入；对重复次数及负载变化画出净收益，而非只报模型推理周期 |
| P1 | 独立重训练和更多种子 | 预先固定协议；多次训练，不重复利用最终测试集调参；给模型与输入变化的区间 |
| P1 | 精简上下文特征 | 与真正无 pilot 的输入模型比较；各消融使用其自身域检查或单独报告共同全维保护，避免混淆 |
| P2 | 真实负载和硬件 | 调度加周期到达/阻塞/优先级差异；内存加真实请求寿命轨迹；有设备后验证真实延迟与能耗 |
| P2 | 工程可靠性 | 覆盖任务创建失败、资源回收、协议模糊输入、全局参数对其他池的影响；避免把重启测试当安全保证 |

建议交接顺序：一名成员完成干净目录构建，一名成员复算表格并读原始记录，一名成员逐页整理答辩，其余成员依据真实能力负责算法/负载实验。上述安排须由团队实际确认，公开仓库不预设姓名。

每次实验至少记录：日期、执行人、源码提交、协议散列、镜像散列、环境版本、输入种子、改动原因、成功/失败原始日志、复核人。先固定协议再采集；失败记录保留。答辩材料引用对应版本，避免把旧表格用于新生成器。
